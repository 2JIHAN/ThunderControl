# Mac 사이에 파일 보내기

두 Mac 모두 ThunderControl 0.9.9 이상으로 업데이트하고 기존 입력 연결을 인증하세요. 이전 버전과도 입력 및 이미지 공유는 유지되지만 파일 전송은 양쪽의 지원이 필요합니다.

1. 보내는 Mac에서 ThunderControl의 **파일** 탭을 여세요.
2. 일반 파일 하나를 탭 안으로 끌어놓거나 **파일 선택…**을 누르세요.
3. 받는 Mac에서도 **파일** 탭을 여세요. **수락하고 저장…**을 누르고 저장 위치와 이름을 선택하세요.
4. 양쪽에 **전송 완료**가 표시되는지 확인하세요.

받는 쪽에서 거절하거나 어느 쪽에서든 **전송 취소**를 누를 수 있습니다. 기존 파일은 덮어쓰지 않습니다. 같은 이름이 있으면 다른 이름을 선택하세요. 수신을 자동 승인하거나 저장한 파일을 자동으로 여는 기능은 없습니다.

## 첫 버전의 범위

- 방향과 관계없이 한 번에 일반 파일 하나를 보냅니다. 빈 파일도 허용하며 크기 한도는 64GiB입니다.
- 폴더와 심볼릭 링크는 보내지 않습니다. 폴더는 먼저 ZIP 파일로 묶어 보내세요.
- Finder의 파일 복사와 다른 Mac에 붙여넣기, 여러 파일 동시 전송과 이어받기는 지원하지 않습니다.
- 내용과 파일 이름을 전송합니다. 원래 실행 권한과 확장 속성을 그대로 복제하지 않습니다. 받은 파일에는 macOS 격리 보안을 적용합니다.
- 마지막 저장 확인이 오기 전에 연결이 끊기면 완료로 표시하지 않습니다. 상대가 이미 저장했을 수 있으므로 다시 보내기 전에 확인하세요.
- 앱의 비정상 강제 종료나 전원 손실까지 이어받거나 자동 복구하지는 않습니다. 그 경우 선택한 폴더에 숨김 부분 파일이 남을 수 있습니다.

## 안전 경계

파일은 기존 입력 및 영상과 다른 암호화 TCP 연결을 사용합니다. 현재 인증한 Thunderbolt 인터페이스와 상대 IP만 사용하고 새 페어링이나 다른 네트워크 경로로 넘어가지 않습니다. 다만 같은 물리 링크와 CPU는 공유하므로 모든 부하에서 입력 및 영상 지연이 없음을 보장하지 않습니다.

수신 승인이 있어야 저장을 시작합니다. 임시 파일에 나눠 쓰고 정확한 크기와 SHA-256을 확인한 뒤 기존 파일을 덮지 않는 방식으로 게시합니다. 잠금, 입력 세션 종료와 안전 상태 변경 시 파일 전송도 중단합니다. 이미 최종 게시가 허용된 마지막 순간의 취소는 완료를 되돌리지 못할 수 있습니다.

## 개발 검사

소스 폴더에서 다음 독립 실행 검사를 빌드하세요. 기본 앱 빌드에는 검사 전용 localhost 포트 주입이 포함되지 않습니다.

```sh
xcrun swiftc -swift-version 5 -D FILE_TRANSFER_SELF_TEST \
  FileTransferStorage.swift FileTransfer.swift Tests/FileTransferTests.swift \
  -framework CryptoKit -framework Security -o /tmp/thundercontrol-file-tests
/tmp/thundercontrol-file-tests
```

컴파일 결과에 macOS 격리 속성이 붙는 환경에서는 실행 전에 해당 로컬 검사 파일의 속성을 확인하고 처리하세요. 다운로드한 임의의 앱이나 다른 파일의 보안 속성을 일괄 제거하지 마세요.

실제 localhost 암호화 송수신, 양방향 빈 파일과 여러 조각 전송, 거절, 취소 후 재전송, 포트 해제, 안전 상태 복구, 파일 경로와 기존 파일 보호, 특수 파일 거부를 검사했습니다. 별도 공격 검사에서는 다른 세션/키, 재전송, 손상, 반사, 잘못된 오프셋 및 해시를 차단했습니다.

파일 선택, 수신 승인과 저장은 같은 제품 UI 구성 요소를 사용한 로컬 검사 창에서 직접 확인했습니다. 실제 두 Mac 사이의 전송은 아직 미검증입니다. 백그라운드 자동화의 실제 드래그 제스처는 적용되지 않아, 드래그 조작 자체의 실사용 확인도 남아 있습니다.
