# 영상 품질과 표시 방식

품질 등급은 절대적인 순위가 아니라 호환성과 대역폭, 처리 지연 사이의 선택이다. 기본 설정은 자동 상한과 반응속도 우선이며, 품질 상한은 두 Mac 중 낮은 쪽을 따른다.

| 상한 | 허용 순서 | 목적 |
|---|---|---|
| 자동 | ProRes LT → Proxy → HEVC → H.264 | 지원되는 최고 등급 |
| 고품질 | Proxy → HEVC → H.264 | ProRes 대역폭을 줄임 |
| 표준 | HEVC → H.264 | 더 낮은 대역폭 |
| 호환성 | H.264 | 기존 영상 프로토콜과의 호환 |

반응속도 우선은 최신 프레임을 즉시 제출한다. 부드러움 우선은 최대 두 장의 제한된 순서 큐와 1초 따라잡기 정책을 사용한다. 어느 방식도 패널 표시를 보장하지 않으며 부드러움 우선은 대기가 늘 수 있다.

## 협상과 적용

인증된 Relay hello의 videoQualityCodec=1이 양쪽에서 확인된 경우에만, 기존 영상 인증과 정확한 기능 확인 뒤에 암호화된 kind11 기능 목록과 kind12 합의 echo를 교환한다. 목록은 4비트 마스크, 상한은 0...3으로 제한한다. 구버전에는 추가 바이트를 보내지 않고 새 송신기가 H.264로 시작한다. 별도의 인터넷 경로나 무선 경로를 추가하지 않는다.

연결 중 상한 변경은 kind13으로 전달한다. 세션 토큰과 제한된 최신 요청 슬롯으로 오래된 작업 및 무제한 작업 누적을 방지한다. 표시 방식만 바꾸는 동작은 품질 혼잡 상태를 초기화하지 않는다. 수신기는 합의된 하드웨어 코덱 목록을 엄격히 검사하되, 상한 변경 도중 이미 전송 중인 이전 코덱 프레임은 허용한다. 상한은 선호 정책이며 실시간 권한 경계가 아니다.

송신 helper에는 허용 목록과 초기 상한을 전달하고, 런타임 상한은 heartbeat 파이프의 0x20...0x23 제어 바이트로 전달한다. 부모 종료 EOF와 기존 안전 감시는 유지한다. frameQueue에서 새 인코딩 입장을 멈추고, 별도 작업에서 기존 콜백과 순서 보장된 출력을 마친 뒤 새 인코더를 준비한다. 준비 실패 시 기존 인코더를 보존하고, 전환 전체에는 4초 안전 제한을 둔다. 첫 새 프레임은 키프레임이다. 가상 디스플레이, 캡처 필터, 입력 연결, 소스 프레임 번호는 교체하지 않는다.

## 혼잡 정책과 한계

2초 동안 30프레임 이상 중 송신 호출 18ms 초과 비율이 25% 이상이면 다음 지원 등급으로 낮춘다. 재하향은 5초 뒤부터 가능하며 자동 상향은 없다. 이 기준은 결정론적 테스트 기준이며 실제 케이블과 기기에서 검증이 더 필요하다. 송신 호출 시간에는 암호화와 전송 잠금 대기도 포함되므로 순수 네트워크 속도 측정값이 아니다.

인코더 생성 실패 및 송신 혼잡은 폴백 대상이다. 디코더 오류, 보안 상태 변경, 네트워크 상실은 기존 안전 중단 정책을 유지한다. ProRes 엔진 부재를 소프트웨어 디코딩 불가능과 동일시하지 않지만, 이 등급 협상은 낮은 지연을 위한 하드웨어 지원 범위로 보수적으로 제한한다.
