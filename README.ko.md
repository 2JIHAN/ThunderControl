# <img src="docs/assets/app-icon.png" width="32" height="32" alt=""> ThunderControl

Thunderbolt로 두 Mac을 직접 연결하고, MacBook의 키보드와 트랙패드, 화면으로 Mac mini에서 작업하세요.

**[Apple Silicon용 다운로드](https://github.com/2JIHAN/ThunderControl/releases/download/v0.8.28/ThunderControl-0.8.28-macOS-arm64.zip)** | [릴리스 안내와 체크섬](https://github.com/2JIHAN/ThunderControl/releases/tag/v0.8.28)

v0.8.28(빌드 58)은 Apple Silicon Mac 두 대를 위한 실험용 사전 릴리스입니다. 화면 공유에는 macOS 14 이상이 필요합니다. 전체 빌드·메모리 회귀 테스트·Developer ID 엄격 서명 검증은 통과했습니다. 2026-10-22 Apple 공증을 받았고 공개 ZIP에 공증 티켓을 부착했습니다. 공개 파일을 다시 내려받아 체크섬, 엄격 서명 검증, 티켓과 Gatekeeper의 Notarized Developer ID 판정을 확인했습니다.

![MacBook의 키보드와 포인터 입력은 Mac mini로, Mac mini의 확장 화면은 Thunderbolt Bridge를 통해 MacBook으로 전달됩니다.](docs/assets/overview-ko.svg)

*앱 스크린샷이 아닌 연결 개념도입니다.*

## 확장 화면과 업데이트 확인 (0.8.28)

입력 **보내기** 쪽인 MacBook에서 **현 기기를 가상 디스플레이로 사용**을 체크하면 됩니다. 입력 연결이 인증되면 연결된 받기 Mac이 확인된 상대 경로로 확장 화면을 만들고 자동 전송합니다. 별도 화면 IP 입력이나 화면 송수신 버튼 조작은 없습니다. 체크를 해제하면 입력 연결은 유지한 채 영상만 종료합니다. 양쪽 모두 새 버전이 필요하며, 구버전 상대와는 입력만 유지하고 이 자동 화면 요청은 사용하지 않습니다. 받기 Mac의 화면 기록 권한과 기존 안전 조건은 여전히 필요합니다. 0.8.28에는 **업데이트 확인…**과 새 버전 안내도 포함됩니다. GitHub 릴리스 페이지를 열며 앱을 자동 다운로드하거나 교체, 재실행하지 않습니다. 자동 확인은 최대24시간에 한 번 GitHub 공개 릴리스 API에 요청하며, 수동 확인은 바로 실행합니다. 계정 인증 정보는 전송하지 않습니다. Developer ID 서명과 Apple 공증을 통과했고 티켓을 부착했습니다.

## 할 수 있는 일

- **MacBook으로 Mac mini에서 작업하세요.** 앱은 mini에서 실행하고, 키보드와 포인터, 스크롤은 MacBook에서 조작합니다.
- **HiDPI 작업 공간을 추가하세요.** 기존 모니터를 복제하는 대신 가상 확장 화면을 만듭니다. 2배 HiDPI와 macOS 기본 전체화면을 지원합니다.
- **화면 배치를 그대로 이어 쓰세요.** 확장 화면 위치를 Mac 조합별로 저장하고 다음 연결에 다시 적용합니다.

ThunderControl은 두 Mac 사이의 전용 Thunderbolt Bridge를 사용합니다. Wi-Fi나 인터넷을 통한 원격 접속용 앱은 아닙니다.

## 두 Mac 연결하기

1. **양쪽 Mac에 설치하세요.** ZIP을 내려받아 릴리스의 `SHA256SUMS.txt`와 비교한 뒤 압축을 풉니다. 기존 앱을 종료하고 `/Applications`에 복사하세요. 이전 앱은 복구용으로 보관해도 됩니다. 업데이트 때문에 페어링, Keychain, 권한을 초기화할 필요는 없습니다.
2. **Thunderbolt 케이블로 연결하세요.** USB-C 단자 모양만 같다고 되는 것은 아닙니다. 양쪽 Mac의 네트워크 설정에서 Thunderbolt Bridge가 구성되어 있고 활성 상태인지 확인하세요.
3. **입력 역할을 정하세요.** MacBook은 **보내기**, Mac mini는 **받기**를 선택합니다. 양쪽에서 손쉬운 사용과 입력 모니터링을 허용하고, 로컬 네트워크 권한도 요청되면 허용하세요. mini가 연결을 기다립니다. 대기를 중지한 상태라면 **대기 재개**를 누르세요.
4. **Mac mini와 페어링하세요.** MacBook에서 mini를 선택하고 **연결**을 누릅니다. mini에 표시되는 PIN 입력 안내에 따라 MacBook의 코드를 확인하세요. 본인이 요청한 연결만 승인하세요.
5. **MacBook을 화면으로 사용할지 선택하세요.** 보내기 화면에서 **현 기기를 가상 디스플레이로 사용**을 체크하면 인증된 받기 Mac이 확장 화면을 만들어 자동 전송합니다. 필요한 경우 mini의 화면 기록 권한을 허용하세요. 양쪽 모두0.8.28 이상이 필요하며 별도 화면 IP나 송수신 버튼은 없습니다. 저장된 OFF 설정과 안전 중지는 유지합니다.

MacBook의 **화면 배치**에서 화면 위치를 맞추세요. 배치한 방향의 화면 가장자리로 포인터를 넘겨 두 Mac 사이를 오갑니다.

**보내기와 받기는 입력을 기준으로 한 이름입니다.** 화면은 반대 방향으로 전달됩니다. 영상 창은 보기 전용이고, mini 조작은 별도의 입력 연결이 담당합니다.

## 중지하거나 제어권 되찾기

- **Control+Option+Escape**로 원격 입력을 중지하고 로컬 제어로 돌아옵니다.
- **현 기기를 가상 디스플레이로 사용** 체크를 해제하면 입력 연결을 유지한 채 영상만 종료합니다.
- 수동 중지나 비상 중지 후에는 앱 상태를 확인하고 직접 재개하세요. 자동 복원은 이 중지 상태나 저장된 OFF 설정을 덮어쓰지 않습니다. mini에서도 로컬 키보드를 사용할 수 있도록 두세요.
- 입력을 보내는 앱이 일반적인 이유로 전면에서 벗어나면 입력은 로컬로 돌아가지만 인증된 연결과 영상은 유지합니다. 보안 입력(Secure Input)만으로 세션을 끊지 않으며, 보호된 이벤트 전달은 계속 macOS가 제한합니다. 잠금, 잠자기, 세션, 경로, 권한과 캡처 검사는 유지합니다.
- 영상 창은 macOS 기본 전체화면 진입이 확인된 뒤 영상을 표시합니다. 진입 실패나 시간 초과 시에는 사용할 수 있는 일반 창으로 표시합니다.

기기 목록에 mini가 없다면 케이블, Thunderbolt Bridge, 로컬 네트워크 권한과 mini의 수신 대기 상태를 확인하세요. 입력은 연결되지만 화면이 보이지 않는다면 mini의 화면 기록 권한과 송신 쪽 체크박스와 양쪽 앱 버전을 확인하세요. 문제 해결의 첫 단계로 페어링을 초기화하지 마세요.

## 사용 전 알아둘 점

이전 v0.8.25/v0.8.26의 로컬 검증은 macOS 27.2에서 진행했습니다. v0.8.28은 전체 빌드와 메모리 전용 회귀 테스트를 통과했습니다. 0.8.28 배포판의 Developer ID 서명과 Apple 공증을 확인했습니다. 공개 작업으로 설치 앱을 변경하지는 않았습니다. 실제 두 Mac 검증은 아직 수행하지 않았습니다. 실제 두 Mac 간 입력부터 화면 표시까지의 지연, 기본 Mission Control 제스처, 폭넓은 macOS 호환성은 아직 검증하지 않았습니다. 프레임 속도와 화질도 보장하지 않습니다. 자세한 내용은 [검증 범위](docs/VERIFICATION.md)를 확인하세요.

일부 화면 기능과 시스템 제스처는 비공개 macOS 인터페이스를 사용하므로 OS 업데이트 후 동작이 달라질 수 있습니다. Gatekeeper와 SIP는 켜 두세요. Apple 공증이 독립적인 보안 감사를 뜻하지는 않습니다.
